Overview summary

Repair decision workflow

Confidence is scored by the validation-calibrated model. A repair is accepted only when it meets the configured threshold; otherwise the system refuses the repair, marks it Unresolved, and withholds the output.

Evaluation covers diagnosis, status assignment, confidence reliability, repair acceptance/refusal, reconstruction error, and abstention—not reconstruction error alone.

Deterministic fault-scenario lab

Change the injected input scenario to observe how diagnosis, calibrated confidence, status, repair acceptance/refusal, and error respond. The selected chart sensor is the first affected channel; additional channels follow the project sensor order. Severity is measured in robust training-set sensor scales. Spikes last one second. The same scenario parameters always produce the same input. Reference readings are used only for scoring after inference and are not returned.

Choose a fault scenario and run it to compare the complete repair decision.

Live telemetry (recorded-cycle replay)

This is recorded data played through a SIMULATED clock, not a live acquisition feed. The dashboard streams one stored 1 Hz average per simulated second, accumulates a complete 60-second cycle, and only then runs the existing offline repair pipeline. No repair is performed instantaneously per second.
